# 静观 TV Android 2.0.14 · 清单多镜像 + 代理一致性 + 状态说人话

上一版把网络层统一成一条通道，本版处理的是「不同设备、不同网络条件下怎么表现得一致」：没有代理的电视要能持续收到官方清单更新，配了代理的设备要真的吃到代理，源管理里的状态要让人一眼看懂是源的问题还是网络的问题。

## 改动

- **官方片源清单改为多地址**：主地址仍是 GitHub Raw，另备 jsDelivr、ghproxy 等镜像。主地址拉不到就依次换镜像，任何一个能通就完成同步；全都拉不到才沿用本地已有配置（不会动用户已装的源）。此前只有电视这类直连受限的设备会「永远收不到后续的清单更新」，现在更新通道本身不再单点。
- **自建通道尊重系统代理**：2.0.13 的 IPv4 回退是自建 socket，不经过系统代理；正常请求（HttpURLConnection）会走。于是同一台设备上可能出现「正常请求走代理、回退请求绕过代理」的分裂行为。本版让自建通道同样查询系统代理：HTTP 代理用 CONNECT 隧道打通后再做 TLS，SNI 仍按原主机名；SOCKS 在 Android 上没有可用的实现，直接忽略（用 SOCKS 的人一般开着 VPN，流量本来就整体走隧道）。
- **失败原因写全两段**：此前 IPv4 回退失败时会保留最初的 IPv6 错误，用户只能看到 `ENETUNREACH`，看不到 IPv4 直连的真实结果（是连接被重置还是超时）。现在会写成「IPv6 不可达（…），IPv4 直连也失败：…」，分得清是源挂了还是网络不通。
- **服务端返回错误状态时也换地址族重试**：延续 2.0.13 的做法，把「边缘线路回错页」这种情况也纳入重试。

## 不做治理，只做多路

本版**不替换、不清理**清单里的任何一个源。某个源在你的网络下测不通，就只是这个源不可用，不影响其他源；应用里任何一个源失败都不会中断整轮搜索，测活也是并发的。有代理的设备自然会多出一批可用源，这是用户自己的网络条件，不需要应用替用户判断哪些源「值得留」。

## 保持不变

- 包名 `com.wangshaojie.libretv`、签名和资产文件名规则不变，可直接覆盖升级，源配置、收藏和观看记录都保留。
- 2.0.13 的自建 IPv4 通道（正确的 SNI 与证书校验）与老系统 TLS 1.1/1.2 补齐、2.0.12 的单一通用安装包、2.0.11 的详情页直接换片源都保持原样。
- 应用不请求通讯录、定位、摄像头或全盘存储权限；启动时的清单请求只下载一份公开的源地址列表，不上传任何本地数据，也不上报使用统计。

## 验证

- 新增单元测试：清单地址必须是多个互不重复的 https 镜像且指向同一份文件；错误摘要会截断过长文本；代理查询不会抛异常。
- CI 设备测试仍分两组：Android 5.0 手机（API 21，覆盖证书补丁生效）与 Android TV（API 28，覆盖系统证书库路径），加上单元测试与 Lint 一并在 CI 中运行。
- 本版按约定跳过了真机回归，以上验证以单元测试、Lint 与 CI 设备测试为准。

## 已知限制

- 清单镜像依赖公共 CDN，可能出现个别节点临时不可用；此时会继续尝试下一个地址，最终以本地已有配置兜底。
- 个别站点所在域名在部分国内网络会被拦截或重置握手，这属于网络环境问题，与应用无关；这类源在「源管理」里会显示为连接异常。
- 极少数只提供 IPv6 的服务器仍无法直连，这类站点本来在老设备上也连不上。
