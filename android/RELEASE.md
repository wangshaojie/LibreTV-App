# 静观 TV Android 2.0.11 · 详情页直接换片源 · 修正 2.0.10 的连接问题

2.0.10 为修复部分老电视连不上网的问题改了连接方式。真机复测发现这个改法过头了，本版改正过来，并顺带把「选择片源」的弹窗换成详情页内直接切换。

## 详情页里直接换片源

搜到一部片子时，通常多个片源都有。现在**不用再弹窗二次选择**：点开影片详情，简介下方就是「片源 · N 个可用」的片源行，当前所在片源高亮显示。

- 点任意片源即切换，线路与剧集随即换成该片的，无需退回搜索结果重选。
- 标题行的片源名、收藏按钮状态都跟随当前片源。
- 只有一个片源时不显示这一行，界面保持干净。
- 剧集不会跨片源合并——每个片源各播各的，避免不同源的集数对不上。

## 修正 2.0.10 的连接方式

2.0.10 把所有请求都改成「先解析出 IPv4 地址、用 IP 直接建连」。这样确实让部分老电视能连上 GitHub 上的官方清单，但**代价是所有片源的 HTTPS 握手全部失败**——服务器看到的是 IP 而不是域名，SNI 与证书对不上，片源一个都搜不了。

2.0.11 改为：

- **默认完全走系统行为**：域名解析、SNI、证书校验都不干预，片源搜索与播放和以前完全一样。
- **只有在失败原因确认为「IPv6 地址不可达」时，才改用该主机的 IPv4 地址重试一次**：用 IP 建连的同时把原主机名放进 `Host` 头，HTTPS 的证书仍按原主机名校验，没有降低 TLS 安全性。
- 确认需要走 IPv4 的主机会被记住，之后不再重复撞一次不可达的 IPv6。

## 真机验证

在真实电视（乐视 X3-43S，Android 5.0.1）上装本版验证：

- 全源搜索正常：搜索「hello」返回 46 部影片，与 2.0.9 一致；片源站点的 HTTPS 不再失败。
- 官方清单正常：启动时自动同步成功，源管理显示「我的片源 · 16」，手动刷新提示「16 个源可用」。
- 日志可见清单请求先因 IPv6 不可达失败，随后自动改用 IPv4 重试成功。
- 详情页片源行正常：一部有 4 个来源的影片显示「片源 · 4 个可用」，当前片源高亮；切到另一个片源后，标题行、线路、剧集都随之更新。

## 保持不变

- 包名 `com.wangshaojie.libretv`、签名和资产文件名规则不变，可直接覆盖升级，源配置、收藏和观看记录都保留。
- 2.0.10 的官方片源清单、2.0.9 的清单合并语义、2.0.8 的连接中控制面板、2.0.6 的直播自动重连、2.0.7 的全屏沉静式播放都保持原样。
- 应用不请求通讯录、定位、摄像头或全盘存储权限；启动时的清单请求只下载一份公开的源地址列表，不上传任何本地数据，也不上报使用统计。

## 已知限制

- 清单地址在 GitHub Raw 上。Windows 版由本地服务拉取、会跟随系统代理，受网络影响较小；Android 版是客户端直连，在部分网络环境下可能拉取不到——此时会静默使用本地已有配置，功能不受影响。
- 极少数只提供 IPv6 的服务器仍无法直连，这类站点本来在老设备上也连不上。
