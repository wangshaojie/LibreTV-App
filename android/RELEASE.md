# 静观 TV Android 2.0.10 · 老电视连不上网的修复

2.0.9 上线官方片源清单后，有用户反馈部分老电视启动时拉不到清单，源管理里点「官方清单」也没反应。

## 问题原因

不少老电视（Android 5 / 6 时代的机型）所在的路由器会给域名返回 IPv6 地址（AAAA 记录），
但电视本身只有链路本地 IPv6 地址、而且**没有配置 IPv6 路由**。

Android 5.0 的底层网络库在这种情况下会把 IPv6 地址排在 IPv4 之前去连接，
连接失败拿到「Network is unreachable」后**不会自动回退到 IPv4**。
于是所有带 AAAA 记录的站点都连不上——包括官方片源清单所在的 GitHub Raw。

## 改动

- **连接前自己解析主机名，挑一个 IPv4 地址直接建连**：用 IP 作为 URL 主机，同时把原主机名放进 `Host` 请求头，
  让服务端看到正确的域名。
- **HTTPS 证书校验仍按原主机名进行**：委托系统默认校验器按原始域名核对证书并走 SNI，没有跳过校验、没有降低 TLS 安全性。
- **拿不到 IPv4 地址时退回系统默认行为**，不会因此让原本能连的设备连不上。
- 该改动统一作用在所有 HTTP / HTTPS 请求上，不只是官方清单。

## 保持不变

- 包名 `com.wangshaojie.libretv`、签名和资产文件名规则不变，可直接覆盖升级，源配置、收藏和观看记录都保留。
- 2.0.9 的官方片源清单、2.0.8 的连接中控制面板、2.0.6 的直播自动重连、2.0.7 的全屏沉静式播放都保持原样。
- 应用不请求通讯录、定位、摄像头或全盘存储权限；启动时的清单请求只下载一份公开的源地址列表，不上传任何本地数据，也不上报使用统计。

## 验证

- 新增 6 项单元测试，覆盖 IPv4 / IPv6 混合解析结果下的地址挑选（IPv4 排在首位、排在末位、只有 IPv6、空结果）。
- 已在真实电视（乐视 X3-43S，Android 5.0.1）上安装本版本验证：启动无任何连接失败日志，源管理显示 16 个官方源，
  手动刷新提示「16 个源可用」且不产生重复条目；删除过的官方源不会被加回，手动停用的源刷新后仍保持停用。
- 上述测试与既有的四组手机 / TV 设备测试一起在 CI 中运行。

## 已知限制

- 清单地址在 GitHub Raw 上。Windows 版由本地服务拉取、会跟随系统代理，受网络影响较小；Android 版是客户端直连，
  在部分网络环境下可能拉取不到——此时会静默使用本地已有配置，功能不受影响。
- 极少数只提供 IPv6 的服务器仍无法直连，这类站点本来在老设备上也连不上。
